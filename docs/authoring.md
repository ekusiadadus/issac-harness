# 環境制作と画質レビュー

## 参照写真と寸法

作業者から見える全景と、ロボットのカメラが実際に識別する面を一つずつ選ぶ。撮影位置・距離・姿勢、対象の幅、光源の位置を記録する。現物を撮れる場合は、寸法基準とグレーカードを入れた参照カットも残す。素材写真を現場全体の照度やカメラ校正の根拠にするには、別途その測定が必要になる。

例えば 130 mm 幅のラベルを 480 px 幅で撮る場合、画像上の必要密度は約 3,700 px/m。ラベル面の UV に原寸 1,300 px を一回割り当てると 10,000 px/m となる。図柄の一番細い線が何画素に写るかは、解像度、斜視、レンズ、フィルタでも変わる。最終 PNG の読み取り結果で合わせ込む。

## 形状・UV・物理

- 寸法資料からシルエット、板厚、隙間、面取り半径を決める。接写で影が落ちる折り返し、把手、段差は形状として作る。紙の印刷や細かな擦れは面に載せ、剥がれやめくれの厚みが見える箇所に幾何を使う。
- UV は表面の実寸で割り当てる。継ぎ目は重要な観察面から外し、木目は板の長軸、研磨跡は加工方向と合わせる。床の広い面は規則的な繰り返しを俯瞰と斜めの両方で確認する。解像度を上げるときは、先に画面上で不足する面を特定する。SimReady 資料の目安は 4K 時に 2,048 px/m。小物・遠景・印字は観察距離で予算を変える。[NVIDIA の UV ガイド](https://docs.omniverse.nvidia.com/simready/latest/simready-asset-creation/uv-best-practices.html)
- ビジュアルメッシュと近似コライダーの支持面を合わせる。箱底・台・床など水平な部分を `[[supports]]` に登録すると、合成後のワールド境界で XY の重なりと上下の隙間を mm 単位で確認できる。斜面、くぼみ、動く荷物は接触点・姿勢・速度を物理ステップ中に測る。複製する部品は同じ USD を参照し、動的部品の原点・質量・慣性・摩擦を記録する。[NVIDIA のモデリングガイド](https://docs.omniverse.nvidia.com/simready/latest/simready-asset-creation/modeling-best-practices.html)

## 材質とテクスチャ

| 入力 | ポータブルなレビュー材質での扱い | 目視で確認するもの |
|---|---|---|
| Base color | 照明や強い影を除いたカラー画像。LDR 画像には `sourceColorSpace=sRGB` を明示 | 紙の白、塗装色、木目の方向。光源を動かすと影が正しく移るか |
| Roughness / metallic | `raw` で読む。ORM は各入力へ実際のチャンネルを接続。均質な材質の粗さは明示した 0–1 の値でもよい | 大きな面光源の反射幅。裸金属、酸化、塗膜、紙の違い |
| Tangent normal | OpenGL（+Y）を使う。DirectX 素材は緑を反転して由来に記す。符号なし RGB は `scale=(2,2,2,1)`、`bias=(-1,-1,-1,0)`、`raw` | 斜光で凹凸が反転しないか。面取りのハイライトと微細な荒れが区別できるか |
| UV / スケール | `UsdPrimvarReader_float2` → 必要なら `UsdTransform2d` → `UsdUVTexture.st`。物体ごとの実寸リピートを記録 | 引き伸ばし、繰り返しの周期、ラベルの向き、テクスチャの継ぎ目 |

この検査は `preview` 用途のバインディング（継承・面別割当・allPurpose フォールバックを含む）から、実際に接続された universal `UsdPreviewSurface` を追う。データマップの色空間を推測に任せず、画像を開いて確認する。ポータブル層には Pillow で復号できる画像を使う。フル品質の MDL・MaterialX・ガラス・塗膜を使う場合は、それを保持して同じ材質にプレビュー面を追加し、最終の RTX 画像でフル品質側を確認する。[OpenUSD のシェーダー仕様](https://openusd.org/release/spec_usdpreviewsurface.html) · [NVIDIA の材質ガイド](https://docs.omniverse.nvidia.com/simready/latest/simready-asset-creation/material-best-practices.html)

均一色の塗装面や磨いた平面を表現する場合、対応する定数・幾何法線の理由を記録できる。下記は粗さのマップに実際の微細な変化がある仕上げの例。各可視材質を特徴づけるテクスチャを少なくとも一つ接続する。

```toml
[uniform."/World/Materials/CoatedPanel"]
diffuseColor = "単色の焼付塗装。試料に合わせた色を線形 RGB の定数で指定"
normal = "表面の起伏は撮影距離で見えず、塗膜の粒子を粗さマップで表現"
```

## 照明とカメラ

最初に光源の寸法・向き・高さを合わせる。窓や面照明の面積は落ち影の柔らかさと金属の反射形状に現れる。環境光に HDRI を使う場合は原本、回転、露出、利用条件を保存する。光源を消しても残る模様は、ベースカラーに陰影が焼き込まれている可能性がある。露出、ホワイトバランス、表示変換を固定してから材質を比較する。HDRI の光と直射光を二重に足していないかも見る。

USD のレンズ・フィルムバックは 1 scene unit の 1/10。1 m/unit で 58 mm を指定する値は `0.58`、36 × 24 mm のゲートは `0.36 × 0.24`。合焦距離とクリップ距離はメートルで入れる。焦点距離とゲートを同じ倍率で誤ると画角だけは合う。`focal_length_mm` に仕様値を入れて取り違えを検出する。ロボットカメラでは、校正値と同じ解像度・主点・歪みモデルで追加検証する。[OpenUSD のカメラ単位](https://openusd.org/release/api/class_usd_geom_camera.html)

## 画像を採用する前に

1. 全景を同じ画角で並べ、スケール、床への接地、主光源の方向、影の落ち方を確認する。位置ずれや物理的な浮きを後処理で隠さず、USD の形状・配置で直す。
2. 接写を原寸で開く。紙繊維、印刷、金属のハイライト、縁の厚みを参照写真に合わせる。対象矩形はカメラ投影の境界で、遮蔽物も画素統計に入る。検出が必要な対象には画像そのものを使った判定を加える。例では箱の指定領域だけを ZXing で読み取る。
3. 通常照明から天井灯だけを −2 EV にしたときの読み取り、暗部、ハイライトを比べる。サンプルではカメラと対象を固定したまま、天井灯の強さが 1/4 になる。素材の比較では照明を固定し、変えた材質だけをレイヤーで差し替える。
4. 新しい入力・設定は新しい出力先で撮る。判断した人またはエージェントが `review.md` にどの画像のどこを見たかを残す。実カメラを再現する案件では、同じ視点からの実写を横に置き、ずれを記録する。データ生成や学習に広げる場合は、調整に使った条件と評価用に固定した条件の ID を保持する。

単発のステッカー・識別ラベルと繰り返し可能な紙繊維には、異なる UV を用意する。全面にタイルを張る材質へロゴを焼くと、内壁や離れたフラップにも同じ向きで現れる。検証用の `paper.toml` はこの挙動を観察できる。現場の不良・識別ラベルには、実寸の独立メッシュか一意な UV 島を使い、ラベルの枚数・可視率・位置も記録する。複数のカメラと材質を組み合わせ、ほぼ白く飽和した天板や被写体の印刷面を個別に確認する。

タイル貼りを意図した面は `campaign texel-check SCENE --mesh /Path/To/Mesh --out report.json` で確認できる。対象距離で必要な texel/m を `--min-texels-per-metre` で指定する。ワールド変換後のメートル、画像解像度、面ごとの UV から最も粗い方向の密度を計算する。PNG を範囲外まで貼る面は `wrapS` と `wrapT` を確認する。荷扱い印のように一面に一度だけ貼る印刷物には、対象面内の専用 UV を使う。[テクスチャ密度の測定](texture-scale.md) · [荷扱い印の配置](surface-marks.md)
