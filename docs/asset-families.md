# USD asset families

`harness.asset_family` builds a variant family from existing USD assets. Each input must declare a transformable default prim, `upAxis = "Z"`, and `metersPerUnit = 1`. The tool checks available dependencies and visible extent, then authors relative references. It never copies source geometry or textures. Keep the referenced assets in the same relative directory layout when moving the family.

```sh
uv run --locked python -m harness.asset_family \
  --variant cracker=examples/campaign/ycb/models/obj_000002.usdc \
  --variant sugar=examples/campaign/ycb/models/obj_000003.usdc \
  --default cracker --out examples/campaign/families/retail_package.usda
```

The family exposes `/Asset` as its default prim and `geometry` as its variant set. The source mesh sits under `/Asset/Geometry`; each variant moves its visible base to local Z = 0. Instance prims can reference the family and select variants independently. The optional `--variant-set` names another set.

The independent retail-package example has two instances of the same class on a 0.84 × 0.60 m paper-textured surface. Its cracker and sugar meshes and photo atlases are the existing [YCB BOP files](../examples/campaign/ycb/sources.json), with terms in [YCB-LICENSE.txt](../examples/campaign/ycb/YCB-LICENSE.txt). The paper fleck texture is generated by the example script. The authored camera and studio lighting are starting estimates from `harness.author.initialize`, not measured capture conditions.

```sh
uv run --locked python -m examples.campaign.families.build
uv run --locked python -m harness.campaign plan \
  examples/campaign/families/capture/campaign.toml \
  --seed 0 --frames 8 --out examples/campaign/families/plan.json
```

With seed 0 and eight frames, each instance receives both `cracker` and `sugar` choices. The plan is reproducible; no render or image acceptance is implied by the USD composition checks. To use other assets, pass their USD paths to the family CLI and reference its output from a metered Z-up scene, then run `harness.author.initialize` on that scene.

When UV coordinates extend over several paper tiles, author `inputs:wrapS` and `inputs:wrapT` on the USD texture. The first L4 render showed one light paper tile on an otherwise dark surface. The geometry and instance tests had passed. The example now sets both axes to `repeat`.
